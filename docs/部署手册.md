# 部署手册

> 覆盖三种场景：**Docker 一键部署**（推荐）、**Linux 服务器部署**、**本地开发**。
> 末尾附「故障排查对照表」，出问题先查那张表。

---

## 一、环境要求

| 场景 | 要求 |
| --- | --- |
| Docker 部署 | Docker 24+ / Docker Compose v2；内存 ≥ 4G；磁盘 ≥ 20G |
| 本地开发 | Windows/Linux；**JDK 21**、Python 3.10+、Node 18+、MySQL 8；Redis/MinIO 可选 |
| 模型 | 不填 API Key 也能跑（Mock）；真实模型建议 DeepSeek（便宜）或通义 |

## 二、Docker 一键部署（推荐）

```bash
git clone <你的仓库地址> enterprise-rag-platform
cd enterprise-rag-platform/deploy

# 1. 准备环境变量
cp .env.example .env
vim .env          # 至少改：MYSQL_ROOT_PASSWORD、MINIO_ROOT_PASSWORD、JWT_SECRET
                  # 想用真实模型：填 DEEPSEEK_API_KEY 并把 LLM_PROVIDER 改成 deepseek

# 2. 一键启动（首次会构建镜像，约 5-10 分钟）
docker compose up -d --build

# 3. 看启动状态（等所有服务 healthy）
docker compose ps

# 4. 看日志
docker compose logs -f backend
docker compose logs -f ai-service
```

**访问入口**

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| 前端 | http://服务器IP | Nginx 统一入口 |
| 后端 API | http://服务器IP/api | |
| AI 服务文档 | http://服务器IP:8001/docs | 直连，便于调试 |
| MinIO 控制台 | http://服务器IP:9001 | 账号见 `.env` |

**默认账号**：租户 `demo` / 用户 `admin` / 密码 `admin123`
（后端首次启动时自动创建，**生产环境请立刻修改**）

### 常用运维命令

```bash
docker compose ps                      # 状态
docker compose restart backend         # 重启单个服务
docker compose logs -f --tail=200      # 跟踪日志
docker compose down                    # 停止（保留数据卷）
docker compose down -v                 # 停止并删除数据卷（⚠ 数据全丢）
docker compose up -d --build backend   # 只重新构建后端
```

### 数据持久化

| 卷 | 内容 | 说明 |
| --- | --- | --- |
| `mysql-data` | 业务数据 | 最重要，务必备份 |
| `minio-data` | 上传的原始文档 | |
| `ai-data` | FAISS 索引 + BM25 + 上传缓存 | 可重建，但重建要重新解析 |
| `redis-data` | 会话缓存 | 丢了影响不大 |

## 三、Linux 服务器部署（生产）

### 1. 前置准备

```bash
# 安装 Docker
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker

# 内核参数（ES/向量库场景建议调大）
cat >> /etc/sysctl.conf <<EOF
vm.max_map_count=262144
net.core.somaxconn=32768
EOF
sysctl -p
```

### 2. 部署

同「Docker 一键部署」。生产环境建议：

- `.env` 里的 `JWT_SECRET` 换成 `openssl rand -base64 48` 生成的随机串
- 数据库/Redis/MinIO **不要暴露到公网**：把 compose 里对应的 `ports` 映射删掉，
  只在 `rag-net` 内部网络通信
- 只暴露 `GATEWAY_PORT`（80）和必要的 443

### 3. 配置 HTTPS（可选但强烈建议）

```bash
# 用 certbot 申请证书
apt install -y certbot
certbot certonly --standalone -d your-domain.com

# 修改 deploy/nginx/nginx.conf，把 80 改成 443 并加载证书
server {
    listen 443 ssl http2;
    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    # ... 其余 location 不变
}
server {                       # 80 跳转 443
    listen 80;
    return 301 https://$host$request_uri;
}
```

同时在 `docker-compose.yml` 的 gateway 服务挂载证书目录：

```yaml
volumes:
  - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro
  - /etc/letsencrypt:/etc/letsencrypt:ro
ports:
  - "80:80"
  - "443:443"
```

### 4. 开机自启

`docker compose` 里的服务都写了 `restart: unless-stopped`，
只要 Docker 开机自启（`systemctl enable docker`），容器就会自动拉起。

### 5. 数据备份

```bash
# MySQL 全量备份（建议加进 crontab，每天凌晨 2 点）
docker exec rag-mysql mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" \
  --single-transaction --routines --triggers rag_platform \
  | gzip > /backup/rag_$(date +%F).sql.gz

# 保留最近 14 天
find /backup -name 'rag_*.sql.gz' -mtime +14 -delete

# MinIO 数据目录
tar czf /backup/minio_$(date +%F).tar.gz -C /var/lib/docker/volumes \
  enterprise-rag-platform_minio-data
```

恢复：

```bash
gunzip -c /backup/rag_2026-10-16.sql.gz | \
  docker exec -i rag-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" rag_platform
```

## 四、本地开发部署

### Windows（本项目验证过的路径）

```powershell
# 1. 初始化数据库（幂等，可重复执行）
powershell -ExecutionPolicy Bypass -File .\scripts\init-db.ps1 `
  -MysqlUser root -MysqlPassword 你的密码

# 2. 一键启动三个服务
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1

# 3. 停止
powershell -ExecutionPolicy Bypass -File .\scripts\stop-dev.ps1
```

只想起某一个：

```powershell
.\scripts\dev.ps1 -Only ai        # 只起 AI 服务
.\scripts\dev.ps1 -Only backend   # 只起后端
.\scripts\dev.ps1 -Only frontend  # 只起前端
```

### 手动分别启动

```bash
# AI 服务（端口 8001）
cd ai-service
python -m venv .venv && .venv/Scripts/activate     # Windows
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python -m uvicorn app.main:app --host 0.0.0.0 --port 8001 --reload

# 后端（端口 8080）
cd backend
mvn clean package -DskipTests
java -jar target/*.jar --spring.profiles.active=dev
# 或 mvn spring-boot:run -Dspring-boot.run.profiles=dev

# 前端（端口 5173，已配置 /api 代理到 8080）
cd frontend
npm install --registry=https://registry.npmmirror.com
npm run dev
```

## 五、故障排查对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 后端启动报 `Communications link failure` | MySQL 没起来 / 密码错 | `docker compose ps` 看 mysql 是否 healthy；核对 `.env` 密码 |
| 前端登录 401 | JWT 密钥不一致 / token 过期 | 检查 `APP_JWT_SECRET`；重新登录 |
| 上传文档后一直 `PENDING` | AI 服务不可达 | `curl http://localhost:8001/health`；检查 `APP_AI_SERVICE_BASE_URL` |
| 文档状态变 `FAILED` | 解析异常（加密 PDF / 格式不支持） | 看 `kb_document.error_msg` 与 ai-service 日志 |
| 检索结果为空 | 没建索引 / 阈值过高 | 调 `/api/v1/kb/{id}/stats` 看 vectors 数量；调低 `SCORE_THRESHOLD` |
| 对话「转圈很久才一次性出结果」 | Nginx 缓冲了 SSE | 确认 nginx.conf 里有 `proxy_buffering off` |
| SSE 60 秒必断 | 读超时太短 | `proxy_read_timeout 300s` |
| FAISS 报 `could not open ... No such file` | Windows 中文路径 | 用 `DATA_DIR` 指定纯英文路径（代码已自动降级） |
| `pip install faiss-cpu` 失败 | 没有对应 wheel | 用 Python 3.10-3.12；或换清华源重试 |
| 前端 `npm install` 卡住 | 走了国外源 | `npm config set registry https://registry.npmmirror.com` |
| Maven 依赖下载极慢 | 没配镜像 | 参考 `README` 或子目录说明配置阿里云镜像 |
| 端口被占用 | 本机已有 MySQL/其他服务 | 改 `.env` 里的端口映射（如 `MYSQL_PORT=3307`） |
| 向量维度不匹配报错 | 换了 Embedding 模型 | 必须重建索引（维度不同不能混用） |

## 六、性能调优建议

| 场景 | 措施 |
| --- | --- |
| 检索慢（>100ms） | 索引换 `IndexIVFFlat`（需训练）；或上 Milvus |
| 文档解析慢 | 用任务队列异步化；PDF 用 `pdfplumber` 或 OCR 按需 |
| 模型调用慢 | 开查询缓存（语义缓存）；重排只在候选 >5 条时启用 |
| 并发高 | AI 服务多 worker（`uvicorn --workers N`）；后端横向扩容 |
| 数据库压力大 | 会话消息冷热分离；`kb_chunk` 按 `kb_id` 分区 |
| 成本高 | 小模型做改写/重排，大模型只做最终回答；`ai_call_log` 按租户限额 |

## 七、安全检查清单（上线前过一遍）

- [ ] `JWT_SECRET` 已换成随机串，不是默认值
- [ ] MySQL / Redis / MinIO **未暴露公网端口**
- [ ] 数据库里 `api_key_cipher` 存的是 AES 密文，不是明文
- [ ] `.env` 未提交进 Git（`.gitignore` 已覆盖）
- [ ] 默认账号 `admin123` 已修改
- [ ] MinIO bucket 权限为私有，未开匿名读
- [ ] 上传接口做了文件类型与大小限制
- [ ] 已配置日志轮转（避免磁盘被日志打满）
